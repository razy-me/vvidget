## Challenged Decisions (D-xxx): agree / disagree + reason

- **D-001 (Tauri v2 + Rust Core)**: **Agree**. Excellent performance, low baseline memory footprint compared to Electron, and full native Win32/WinRT access.
- **D-002 (Spotify Integration via GSMTC)**: **Agree with reservation**. Zero OAuth requirement and local operation are superior to Spotify Web API. However, polling `TryGetMediaPropertiesAsync()` every 500ms violates the spirit of event-driven GSMTC and adds avoidable cross-process IPC overhead.
- **D-003 (Weather Data Source: Open-Meteo)**: **Agree**. Keyless, free, reliable, and privacy-respecting.
- **D-004 (Multi-Window vs Single Dock)**: **Agree with reservation**. Providing both modes is architecturally sound. However, the implementation is broken because `main.hide()` fails due to `SWP_HIDEWINDOW` suppression in `WM_WINDOWPOSCHANGING`.
- **D-005 (Win32 Window Styles & WS_EX_TOOLWINDOW)**: **Agree**. Correct mechanism to omit widgets from Alt+Tab and taskbar without fragile Explorer hooks.
- **D-006 (Background System Metrics Polling)**: **Agree**. Background thread pushing events avoids UI stutter. Calling `block_on` inside the loop should be replaced by cached atomic intervals.
- **D-007 / D-022 (Atomic Config Persistence & Debounce)**: **Agree with reservation**. Atomic file replacement and corrupt recovery are well designed and thoroughly tested. However, the movement debounce mechanism is currently disconnected from actual window movement events.
- **D-010 (Movement Debounce & Display Clamping)**: **Agree with reservation**. Multi-monitor clamping is mathematically sound and well tested. Movement debounce is dead code until window move events are captured.
- **D-011 (GSMTC Session Arbitration & COM Guarding)**: **Disagree on implementation**. Decision claims WinRT calls are executed with a "COM guard", but no COM guard exists anywhere in the codebase.
- **D-012 (tauri-plugin-log & Safe Config Fallback)**: **Agree with reservation**. Plugin setup is clean, but `storage.rs` continues to use `eprintln!` which drops logs in release GUI mode.
- **D-013 (Realistic WebView2 Memory Footprints & Window Destruction)**: **Agree**. Destroying the settings window on close (`window.destroy()`) successfully reclaims ~40MB WebView2 RAM.
- **D-014 (Win+D Desktop Anchoring & Scoped Focus Activation)**: **Disagree on implementation**. Applying `WS_EX_NOACTIVATE` selectively to widgets while leaving Settings interactive is correct. However, suppressing `SWP_HIDEWINDOW` in `WM_WINDOWPOSCHANGING` unconditionally prevents programmatic window hiding.
- **D-015 (DWM Acrylic Material via window-vibrancy)**: **Agree**. Native DWM Acrylic provides true Windows 11 Fluent aesthetic without Mica inactive discoloration.
- **D-016 (Album Art Custom URI Protocol & Timeline Interpolation)**: **Agree**. One of the best architectural choices in the app: eliminates Base64 JSON serialization and avoids 60fps IPC progress spam.
- **D-017 (Type Generation via tauri-specta)**: **Disagree on implementation**. The decision was not carried out: specta attributes exist, but no export pipeline is configured, leading to manual TypeScript type definitions.
- **D-020 / D-024 (Native Win32 WM_MOVING Snapping)**: **Agree with reservation**. Snapping directly in `WM_MOVING` in OS memory delivers 60fps tear-free snapping without React IPC lag. However, `SNAP_TO_EDGES` is hardcoded static and unlinked from config.
- **D-025 (Decoupled Polling for Disks vs CPU/RAM)**: **Agree**. Refreshing Disks every 15s while CPU/RAM polls every 1.5s keeps idle CPU usage well under 0.2%.
- **D-027 (Open-Meteo & Native Windows Geolocation)**: **Agree**. Clean privacy-preserving fallback chain from WinRT to manual/cached coordinates.
- **D-028 (Unified Docking Surface Integration & Window Sync)**: **Agree with reservation**. Dual-mode model is ideal for diverse hardware capabilities, but requires fixing the `main.hide()` bug to function as intended.

## Missing / partially met requirements

- **R1: Win+D Protection & Dual-Mode Window Hiding (Partially Met)**: `WM_WINDOWPOSCHANGING` strips `SWP_HIDEWINDOW` globally, which prevents the `main` window from hiding in independent multi-window mode, causing duplicate widget rendering and exceeding RAM budgets.
- **R2: Widget Movement Persistence (Partially Met)**: While atomic config storage and 500ms debounce exist, window move hooks are not wired to `ConfigManager::save_debounced`, meaning moved widget positions are never saved to `%APPDATA%/Widgetz/config.json`.
- **R2: Config Option `always_on_top` (Partially Met)**: Field exists in `AppConfig` but is never applied to windows.
- **R8: Content Security Policy (Partially Met)**: Capability ACL is properly restricted, but `"csp": null` leaves WebView2 windows without HTTP/asset Content Security Policy.
- **R9: Automated TypeScript Binding Generation (Partially Met)**: Specta macros are attached to Rust models, but automatic export to frontend `.ts` files was not implemented.

## Overall assessment

The backend implementation demonstrates strong architectural fundamentals: native Win32/WinRT integrations (DWM Acrylic, GSMTC, sysinfo, snapping) are written cleanly without external heavy dependencies. Test coverage for pure logic (atomic storage, corrupt recovery, snapping geometry, multi-monitor clamping, sysinfo parsing) is exceptionally high (81 unit tests, all passing).

However, four major issues must be resolved before production release:
1. Fix `SWP_HIDEWINDOW` stripping in `widget_subclass_proc` so `main.hide()` succeeds in independent mode.
2. Hook `WM_EXITSIZEMOVE` or `Moved` events to persist dragged widget positions to `config.json`.
3. Add a COM guard (`CoInitializeEx`) to WinRT background operations.
4. Define a strict Content Security Policy in `tauri.conf.json`.
