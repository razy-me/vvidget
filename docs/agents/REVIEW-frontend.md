## Challenged Decisions (D-xxx): agree / disagree + reason

### D-040 Frontend Lazy Route-Splitting & Memory Reduction: Partially Disagree
- **Reason**: The decision intended to achieve per-widget code isolation and eliminate duplicated dynamic imports across hooks. However:
  1. The `manualChunks` configuration in `vite.config.ts` failed to isolate shared modules (`Card`, `Badge`, `useConfig`). As a result, Rollup placed `Card` inside `widget-resources`, `Badge` inside `widget-spotify`, and `useConfig` inside `widget-weather`. This forced the entry bundle `index-*.js` to statically import all three starter widget chunks, prompting Vite to generate `<link rel="modulepreload">` tags for them in `index.html`. Consequently, every WebView window (including single-purpose widgets like Battery or Clock) loads and evaluates the full JavaScript bytecode of Resources, Spotify, and Weather widgets, failing the memory isolation promise of R5.
  2. The migration to `src/utils/tauri.ts` was incomplete: `useMediaPlayback.ts` was overlooked entirely, `useWeather.ts` retains an erroneous dynamic import fallback, and multiple widgets (`BluetoothWidget`, `QuickSettingsWidget`, `DockContainer`) continue to execute dynamic core import promises.

### D-041 CSS Compositor, Render & Timer Hygiene: Partially Disagree
- **Reason**:
  1. While `ClockFace` successfully decouples render updates from the `ClockWidget` parent, its background timer suspension is incomplete: `scheduleNextTick()` continues to reschedule a 1-second `setTimeout` when `document.hidden` is true, continuing to wake the thread every 1,000ms.
  2. `TrackProgress` in the Spotify widget was not included in timer hygiene updates and continues to fire 4 ticks/sec (`250ms`) regardless of window visibility.
  3. Compositor hygiene was otherwise verified cleanly: 0 occurrences of `backdrop-blur*` and 0 occurrences of `transition-all` exist across `src/`, and `ProgressBar` correctly uses `transition-[width]`.

## Missing / partially met requirements
- **R4 (Native Push over Polling)**: Fully met on frontend hooks (`useMasterVolume` and `useBattery` updated to 60s fallback heartbeat with `document.hidden` pause and native push event listeners).
- **R5 (Code-Splitting & Memory Trimming)**: Partially met. `App.tsx` correctly implements `React.lazy` across all 10 widgets and views, but `vite.config.ts`'s `manualChunks` allows shared component leakage into `widget-resources`, `widget-spotify`, and `widget-weather`, which are statically imported by the main entry chunk and preloaded in all windows via `index.html`.
- **R6 (CSS Compositor & Render Hygiene)**: Partially met. All `backdrop-blur` and `transition-all` instances have been completely removed, and 24h geocoding coordinate caching is implemented. However, background timer suppression in `ClockFace.tsx` (1s loop continues while hidden) and `TrackProgress.tsx` (250ms loop ignores hidden) is incomplete, and `useWeather.ts` has a faulty dynamic import fallback in non-Tauri mode.

## Overall assessment
The frontend architecture has made substantial progress towards hardware-close efficiency: all `backdrop-blur` and unconstrained `transition-all` styles have been excised, `ClockFace` isolates 1-second render cycles from tab/timer state, and `useMasterVolume` / `useBattery` hooks have been converted to native push event listeners with 60-second fallback heartbeats.

However, the per-window memory reduction is currently compromised by an incomplete Rollup chunking configuration in `vite.config.ts`, which causes shared UI primitives and hooks to be co-located inside the starter widget chunks, pulling `widget-resources`, `widget-spotify`, and `widget-weather` statically into the entry bundle and preloading them in all WebView2 windows. Addressing the chunk definitions, completing the `safeInvoke` migration in `useMediaPlayback.ts`, and halting the background timers when `document.hidden` is true will fully realize the intended power and memory savings.
