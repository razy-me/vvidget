## Challenged Decisions (D-xxx): agree / disagree + reason

- **D-001 (Tauri v2 + Rust + Vite/TypeScript)**: **Agree with reservation.** The stack provides great DX, low RAM usage, and full Win32/WinRT access. However, running React 19 across multiple independent WebView2 instances requires strict memory discipline; the docked mode should be promoted as default on low-memory systems.
- **D-004 / D-009 (Dual Layout Mode: Independent Multi-Windows & Docked Surface)**: **Agree with concept, disagree with component implementation.** The dual-mode architecture is well justified, but `ResourceWidget` encapsulating `WidgetContainer` while `Spotify` and `Weather` are bare cards causes visual duplication (nested header in `DockItem`) in docked mode.
- **D-008 (UI Primitives in WP-00)**: **Agree with reservation.** Centralizing `Card`, `ProgressBar`, `Badge`, and `Tooltip` was sound, but `ProgressBar` lacks label customization (`showLabel` hardcodes "Progress") and `Tooltip` suffers from a timer handle overwrite race condition.
- **D-010 (Window Movement Debounce 500ms)**: **Agree with reservation.** Debouncing IPC writes prevents disk thrashing, but the frontend implementation in `useConfig.ts` lacks an unmount cleanup or `beforeunload` flush, risking lost coordinates on quick app termination.
- **D-015 (DWM Acrylic Material via window-vibrancy)**: **Agree with reservation.** Acrylic is superior to Mica for inactive desktop widgets (`WS_EX_NOACTIVATE`), but the CSS token palette in `src/styles/fluent.css` omitted `--fluent-control-bg` and `--fluent-control-active`, degrading UI states.
- **D-016 (Album Art Custom URI & Client-Side Timeline Interpolation)**: **Agree with reservation.** Custom URI protocol streaming and client-side interpolation eliminate IPC spam, but interpolating via 60-144Hz React state updates in `TrackProgress` causes excessive React reconciliation compared to a throttled timer with CSS easing.
- **D-019 (Tailwind CSS v4 via @tailwindcss/vite)**: **Agree with reservation.** Build times and config simplicity are excellent, but Tailwind v4 arbitrary value classes (`bg-[var(--...)]`) fail silently when variables are missing, hiding the missing `--fluent-control-*` tokens.
- **D-022 (Debounced Persistence & Self-Healing Recovery)**: **Agree with reservation.** Backend atomic file replacement and corrupt recovery are rock solid, but `SettingsModal` failing to clear `latitude`/`longitude` when editing `manual_city` causes stale coordinate priority bugs in `useWeather`.
- **D-023 (Lazy Settings Window Destruction on Close)**: **Disagree with UI implementation.** Destroying the settings window on close effectively saves RAM, but having both native OS window decorations (`decorations(true)`) and an in-content faux title bar creates redundant double chrome.
- **D-027 (Open-Meteo & Geolocation with Offline Cache Resilience)**: **Agree with reservation.** Privacy-first geolocation and offline cache fallback are exemplary, but forcing `isOffline = true` inside `getCachedWeather()` causes false offline badge flashes on application startup.
- **D-028 (Windows 11 Fluent Theme & Dock Integration)**: **Agree.** System appearance detection (`matchMedia`) with manual override and cross-window `"config-changed"` synchronization is robust and well executed.

## Missing / partially met requirements

- **R2 (Settings & City Search)**: Partially met. City search input in `SettingsModal` saves the city string to config, but does not trigger geocoding or clear existing coordinates. If `latitude`/`longitude` were previously populated, the widget continues querying the old location.
- **R6 (Lightweight Performance & Idle CPU)**: Partially met. While background worker threads run with low overhead, `TrackProgress` updating React state on every single animation frame (up to 144Hz) causes unnecessary UI thread churn during playback.
- **R7 (Native Windows 11 Look & Feel)**: Partially met. Missing `--fluent-control-bg` and `--fluent-control-active` CSS variables degrade button hover states, tab active indicators, and weather loading skeleton placeholders. Double title bars on Settings window violate native aesthetics.
- **R9 (Code Quality & Robustness)**: Partially met. While TypeScript typechecks cleanly and existing 125 tests pass, the absence of a top-level React Error Boundary leaves widgets vulnerable to fatal white-screen unmounts on unexpected runtime errors.

## Overall assessment

The frontend codebase is well-structured, modern, and adheres strictly to TypeScript strict mode and Fluent design principles. Component modularity, SVG sparklines, custom URI album art integration, and multi-window query routing (`?widget=<id>`, `?view=settings`) are cleanly implemented.

However, three major issues require remediation:
1. Missing CSS tokens (`--fluent-control-bg`, `--fluent-control-active`) breaking tab highlights and loading skeletons.
2. Stale coordinate retention in Settings preventing manual city changes from taking effect.
3. Asymmetric container nesting causing duplicate headers in `DockContainer` for `ResourceWidget`.

Addressing these along with the minor UX and performance refinements (startup offline badge flash, Tooltip timer race, RAF re-render throttling, Error Boundary) will bring the frontend to full production-grade quality.
